# 候选分页、筛选与审批一致性

## 行为与接口

页面候选列表每页25条，按候选编号从大到小排列，支持全部状态、待审批、已批准、已驳回。较新/较旧候选翻页只更新候选区；筛选变化与刷新候选重置到第一页。审批成功后保留当前筛选并重新加载工作台，已处理项自然退出待审批列表。空列表与末页有明确状态；行数是本页数量，不是项目候选总数。

`GET /api/projects/:p/candidates?status=pending&limit=25&before=123` 返回 `{role,candidates,next_before}`。候选对象保持旧聚合接口同样的字段及来源标题。`status`缺省all，仅接受all/pending/approved/rejected；`limit`缺省25，整数1–100；before可省略，或为整数1–2147483647，排除该编号及更大编号。多取一行确定后续游标，无下一页时null。空、重复、越界或未知参数值400，未登录401，非项目成员403。只读者可读取但不显示审批按钮，服务端仍独立检查审批权限。

旧 `/data` 默认不变；`include_candidates=false`跳过候选SQL并省略candidates字段，true与缺省相同，其他值或重复参数400。页面现并行读取审计、事实/历史/候选/来源第一页，审计请求将四个include_*设为false。无数据库迁移或旧数据修改。

## 并发、失败与可访问性

每页在独立只读REPEATABLE READ事务中检查角色及RLS。状态会被审批修改，跨页不是共同快照：待审批列表可能缩短，批准/驳回筛选可能新增匹配项，编号在已翻过范围内的状态变化需刷新第一页查看。新候选也需刷新第一页查看。游标仅是位置，不能代替授权或充当严格时间点导出。

审批仍由原decide事务锁定候选、复核pending状态、检查事实版本并写入审计。并发批准/驳回只能有一个成功；另一请求409。页面提交决定时禁用该条目的两个决定按钮，成功后刷新；409时也刷新并保留冲突提示，避免继续展示已过期审批按钮。事实版本冲突的候选可能仍是pending，必须重新提议而不是盲目重试。刷新失败会显示各区域错误，不隐瞒审批响应。

候选请求有独立代次，旧筛选/旧页不能覆盖新请求。加载时清空旧候选并禁用翻页；503等错误可独立刷新恢复。筛选有label，状态用礼貌播报，翻页后焦点移到标题，禁用控件和键盘焦点可见；不宣称已通过全面可访问性审计。

## 真实测量与限制

2026-11-04，Node24.19/PostgreSQL16.15随机临时库，固定合成语料加2000条填充事实；项目1有2009条候选。此前侧栏（含全量候选）加历史第一页为527885字节；本次来源/审计响应13293字节，候选第一页6412字节（25条），历史第一页4572字节，三者合计24277字节。两种计算都不包含同样独立读取的事实页，也不包含HTTP头，不能当作整个网页大小。测量为未压缩UTF-8 JSON，没有比较SQL耗时或宣称吞吐提升。

`EVALUATION_FILLER_COUNT=2000 npm run eval:retrieval`（需测试管理员EVALUATION_DATABASE_URL）复现；报告candidateScale保存上述数字，并核对省略候选后其余字段不变、候选第一页等于旧列表前25条。原始本次报告为工作区artifacts/candidates-scale-2000.json；默认200档由CI归档。报告记录代码校验值和环境，正式材料应使用同次报告。

来源现已[分页并保留已选依据](source-pagination.md)，审计限定100条，原聚合默认响应仍可很大。分页限制行数不保证固定字节数或SQL扫描工作量；没有新增索引，没有宣称所有响应都已严格有界。
