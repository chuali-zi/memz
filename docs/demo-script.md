# 可重复演示步骤与取证

这是项目建议流程，不是赛事规定时长。短讲可安排约5分钟，分页与来源保持作为扩展；官方演示时间须另行核对。先说明所有种子和测试数据均为合成，模拟客户端不调用模型。

## 自动复现证据（优先）

在测试PostgreSQL已初始化应用角色后，使用README的测试管理员连接分别运行test:system:evidence、eval:retrieval和test:ui:evidence，再运行evidence:package。三项取证创建随机临时库，不重置现有演示库。打包要求当前代码已经提交、工作区干净、报告提交一致。具体命令见[材料打包](evidence-package.md)。

自动流程覆盖完整批准、旧版本冲突、外部候选驳回、只读/项目隔离、四类分页与跨页来源ID保持。图中503是明确故障注入；模拟“另一请求”的决定通过真实HTTP和数据库执行。包内22张图和报告须一起引用，不挑选失败现场冒充通过。

## 现场操作（不重置已有数据）

使用已启动的本机应用和公开owner演示账号。为避免与已有事实冲突，每次选一个新的主体名，例如“演示项目-日期-时分秒”；记录下来贯穿后续步骤。操作会新增演示数据，不删除既有记录。

1. **来源先行**：从“提出候选”区域点击“先添加来源”，添加标题“本次会议纪要（合成）”，正文“本次项目截止日为20号”。确认表单提示新来源已选为依据，点击“返回提出候选”。说明来源内容本身不进入事实。
2. **提议与批准**：主体用本次唯一名称，属性“截止日”，候选值“20号”，基于版本0。提交后指出待审批状态与当前事实未改变，再批准。用主体检索，应出现20号 v1，历史与审计新增记录。
3. **更正可追溯**：添加“负责人更正（合成）”来源，正文“本次截止日更正为15号”。对同主体/属性提议15号、基于版本1并批准。当前值为15号 v2，历史仍保留20号与15号及各自来源。点击当前事实的“查看依据”，展示该版本的来源ID、原文、修订与候选ID；相同标题不等于同一来源。
4. **旧版本不覆盖**：对同主体提议25号、基于版本1。批准应409，当前仍为15号 v2；候选保持待审，需要重新提议或驳回，而不是反复点击批准。
5. **外部文字不执行**：选“外部文档（不可信示例）”来源，对同主体提议30号、基于版本2。提议不会自动改变事实；负责人驳回后查看reject审计。不要把该示例当作完整安全认证。
6. **权限与隔离**：切换viewer，浏览本次事实，提交应403且无审批按钮；切换other，只能看到另一项目。本次提议的主体不应出现。

7. **让接入方实际读取**：在另一终端运行 `MEMZ_QUERY=本次唯一主体 MEMZ_MAX_OUTPUT_BYTES=4096 node scripts/context-client.js`，使用公开viewer身份展示实际JSON：15号、v2、来源原文及修订/候选ID。此处是确定性客户端，不是模型回答；同时回查v1说明旧依据仍在。

最后说明每个列表的单页快照与跨页限制。候选按状态筛选，审批后保持筛选回第一页；来源按标题检索，选中ID跨页保留，空搜索也不悄悄换依据。小演示库未形成多页时使用包内自动生成的规模截图，明确其合成数据规模，不冒称当前现场库已有同样条数。

## 出错时的真实处理

- 401：点击“切换账号”返回登录界面，再登录演示账号；内存会话在服务重启后失效。即使注销返回401，页面也允许返回登录；403、网络错误或服务错误仍显示原错误，不冒称注销成功。
- 403：核对账号角色与项目；不改数据库权限绕过演示。
- 409：展示冲突含义，核对当前版本，重新提议或驳回旧候选。
- 网络/503：来源、候选提交或审批失败会在对应区域提示；输入保留。创建结果不确定时保持本页、原内容和账号不变，恢复后再次提交以复用原幂等键；不要刷新页面或改内容后盲目重试。审批失败先重新读取状态。读取错误用区域刷新控件重试；首次项目列表失败时点击“刷新工作台”重新加载项目，无需退出登录。若返回空项目列表，页面会明确提示切换账号或刷新，不允许向空项目提交。尚未通过的步骤不能讲成已经完成。
- 数据库或浏览器不可用：展示已校验的对应提交材料包，明确这是此前真实取证，不是当前服务实时结果。

正式材料优先选择01–08图解释完整业务流程，再用09–22图补充规模和并发边界；所有图附原报告、提交SHA及CI链接。没有自动报名、付费或外部提交行为。


## 一条命令复现完整故事

```sh
MEMZ_DEMO_BASE_URL=http://127.0.0.1:3000 node scripts/demo-story.js --markdown
```

必须显式指定已启动的本地演示服务；脚本只允许HTTP回环地址和公开演示账号，不接受真实凭据。它会用随机唯一主体新增3个来源、4个候选及2次批准，不删除已有记录，也不自动清理这次演示数据。未指定地址或指定非本地地址时在写入前拒绝。默认输出JSON；--markdown输出可读表格与最终上下文。失败仅输出固定错误码并返回非零，先核对失败阶段，不把失败当完成。

脚本依次验证待审不入上下文、20号v1、15号v2、旧版本409、外部候选驳回、v1原文回查、viewer写入与其他项目读取403。每个结果来自真实HTTP与数据库；随机主体避免把之前演示数据误当本次结果。全部已创建会话在结束或失败时尝试注销。

自动系统测试在随机临时库执行这个独立Node进程，也在旧库升级后执行。core.tap包含唯一的Synthetic reviewer rehearsal result记录；正式材料包从该原始记录生成evidence/demo-story.json与demo-story.md，并在离线校验时比对。材料包首页先链接这份实际故事，再进入六项设计与原始证据。演示不是原子批次：中途失败可能留下部分合成提议，不能声称整段脚本回滚。

## 同一输入的对照阅读

运行上方 demo-story 命令，输出新增“同一输入，两种读取规则”表格。输入只来自该次脚本提交成功的四项合成候选（20号、15号、25号、30号），对照列表在脚本内保存接收顺序。其唯一规则是取最后收到的提议值，不运行聊天产品或模型，不声称代表所有聊天系统。

逐行看五个时点：20号待审时当前事实为空；批准后为20号v1；批准更正后为15号v2；旧版本25号审批实际返回409，当前不变；外部30号被驳回，当前仍不变。表格的Memz列来自每个时点的真实客户端读取，附实际版本、来源ID；原始JSON还保留四项候选ID、输入版本及旧v1来源。

因此“最后提到的值”与“已批准的当前值”可以不同。来源、候选、修订、当前指针、审计及事务约束将这一区别显式保存并可核对。来源中的文字不自动转成事实；提议也未自动核验是否忠实于原文，负责人承担审批判断。此演示验证状态与可追溯性，不验证智能效果、外部真实性或性能优越性。
