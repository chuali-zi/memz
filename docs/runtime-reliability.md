# 单机运行的资源与故障边界

本页说明工程保护，不改变公开账号、本机HTTP和单进程演示的范围，不表示生产身份认证或可公开部署。

## 会话

每个服务进程最多保留1000个内存会话，8小时固定过期，不因读取延长。新登录清理已过期项；全部容量被有效登录占用时返回503及 `Retry-After: 60`，不驱逐已有用户、不下发新cookie。注销释放容量。成功重新登录会旋转sid和CSRF，并撤销当前浏览器提交的旧sid；其他浏览器会话不变。错误凭据和Origin校验失败不撤销旧登录。会话不存账号密码。

这不是速率限制。公开演示账号仍可被反复登录直至容量满；服务重启使所有内存会话失效，多个进程没有共享会话。不能用提高容量替代身份认证、速率限制和共享会话方案。

## 数据库

连接池最多10个连接，checkout排队与新连接握手各受5秒连接等待约束；每条PostgreSQL语句默认10秒服务端期限，每次驱动query读取等待15秒。`DATABASE_URL` 中同名的 `connectionTimeoutMillis`、`statement_timeout`、`query_timeout` 参数会移除，由应用固定设置；其他连接配置继续保留。非法URL只产生固定错误，不保留其内容/cause。

这些不是整个HTTP请求、整个多语句事务或任意JavaScript callback的总时限；多个依次执行的语句可能累计更久。当前没有业务SQL或连接池的生产容量承诺。调整阈值应先测量实际负载与慢查询，再修改并运行回归。

事务局部身份仍通过 `set_config(..., true)` 设置。普通失败先ROLLBACK后归还健康连接；服务端取消也要求回滚。连接断开或驱动读超时直接丢弃连接，避免把ROLLBACK排到尚未完成的查询后继续等待；ROLLBACK自己失败也销毁连接，并向调用方保留原始异常。checked-out期间的连接error事件有监听器，避免后台断线成为未处理进程异常。

数据库不可用/超时映射为503。只读请求可以人工重试；写请求保守提示结果可能不确定，尤其COMMIT的回执丢失时不能猜测是否提交。服务端不会重试事务。来源/候选创建恢复后可保持原内容和原幂等键重试；审批需先核对实际状态，不能自动重放。日志只输出白名单错误代码，不输出SQL、参数、连接对象或异常中的凭据。

## 验证

核心系统测试包含真实PostgreSQL的statement取消、驱动超时、活动backend终止、RLS身份清理与池饱和恢复；握手黑洞测试使用本机TCP服务与合成凭据。单元测试另外覆盖COMMIT不确定、ROLLBACK失败保留原错误和坏连接释放，不把mock当作真实数据库故障证据。

使用推荐隔离runner：

```sh
SYSTEM_TEST_DATABASE_URL=... npm run test:system:evidence
npm run test:outage
```

必须使用测试管理员连接。outage测试创建自己的临时PostgreSQL容器，仅停启和清理自己创建的实例，覆盖已提交后丢响应、同键重放、无自动写重试和项目隔离。新代码仍需对应提交的完整系统/故障测试；文档描述不是测试已通过的替代证据。

真实COMMIT确认丢失回归见 `test/commit-ack-loss.test.js`：本机有界协议代理只对随机测试库丢弃数据库COMMIT完成帧；独立直连在重试前确认业务行、审计和幂等回执已提交，HTTP保持503不确定状态，原键重放返回同ID且不新增记录。来源及待审候选分别覆盖，候选不自动批准。代理不记录认证或协议内容，所有连接/进程/临时库清理；这不是任意网络分区或生产故障的完整证明。
