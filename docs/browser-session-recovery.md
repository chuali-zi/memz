# 浏览器内的同账号会话恢复

公开演示身份与密码仍只用于本机原型，不是生产认证方案。这里复用现有登录接口，没有增加认证提供方、自动登录、自动重试或跨刷新存储。

## 何时暂停变更

浏览器已接受一次有效登录后，如果当前会话代次发出的项目 API 请求收到完整、有效的 401 错误回执，页面会显示独立的会话恢复区域，并暂停创建、审批、驳回、模拟候选和“填写新候选”。已经显示的内容和表单仍可阅读、编辑。

登录和退出接口的 401 不触发这条项目会话规则。正文不完整、超限、无效 JSON 或非法 UTF-8 的 401 也不是确认会话失效的完整回执；原有不确定写入规则保持不变。403 仍按既有项目读取权限拒绝规则处理，不能一概认作会话过期。

## 人工恢复步骤

1. 保持本页和原始写入内容不变，在“当前演示账号会话”区域手动输入密码并重新登录。账号固定为最初已接受登录时实际提交的 username；不使用显示名，也不读取之后被改变的隐藏账号选择框。密码每次尝试后清空，不写入存储或日志。
2. 页面先验证完整登录回执，再更新内存中的 CSRF 和会话代次。无效回执或登录失败不会被接纳为恢复成功；错误留在独立的状态区，切换项目也不会隐藏这条同账号登录错误。
3. 有效登录后仍暂停变更，重新读取当前项目。只有当前会话代次的有效工作台角色回执才解除会话恢复期间的访问等待；读取失败可用“刷新工作台”手动重试。403 继续受项目访问拒绝闩保护，viewer 继续只读。五个列表仍各自读取、验证和提交，不是跨请求的同一快照，也不保证之后权限不变。
4. 核对原来的未确认请求后，再手动提交。恢复流程不会自动创建或审批。原始路径和 JSON 内容相同的未知创建仍保留原来的幂等键及不确定状态；详见[创建幂等合同](idempotent-creation.md)。

同一项目恢复保留表单草稿、已选来源、尚未完成的键和原有不确定/审批未确认提示，包括模拟客户端使用的全局提示。恢复进度和错误使用独立的状态区，不覆盖这些提示。用户主动切换项目仍遵循原有工作区切换规则；会话恢复状态本身属于当前账号，不能因项目导航丢失。用户已经在编辑草稿时，不抢走焦点或光标。

有效重新登录后，旧会话请求晚到的 401 不会再次使新会话失效。正常工作区代次、列表请求代次、写入回执和审批版本校验仍独立生效。

## 切换账号与限制

“切换账号”继续执行退出并重新加载页面，清空内存键、草稿和选择，是账号之间的隐私边界。刷新、关闭页面或切换账号后，未知请求不能依靠本页键恢复；应先核实先前结果，不能靠重填相同内容承诺去重。

恢复和创建回执的校验只是客户端接纳规则，不是服务端已经提交或回滚的独立证明。会话恢复也不提供离线队列、密码保存或跨账号延续草稿。

## 验证范围

`test/product-experience.js` 使用真实 Chromium、真实静态页面和明确合成的 API 回执，覆盖来源/候选未知创建后的 401、人工同账号恢复和同键重试、坏登录回执、访问 503/403、viewer、旧会话晚到 401、项目导航中的登录错误、键盘焦点及切账号清理。合成测试不证明真实数据库提交、服务重启恢复或模型质量；这些层级需要单独的真实集成证据。

`test/browser-session-epoch.test.js` 在隔离 VM 中加载完整 `app.js`，替换最小 DOM/FormData 和五个列表加载器，独立检查会话代次、回执接纳和写入闩；所有 transport 都是合成的。

`npm run test:session-recovery` 是显式运行的真实 CLI → HTTP → PostgreSQL 与 Chromium 集成。需先提供本机专属测试集群的 `SESSION_RECOVERY_DATABASE_URL`（可建删随机库，已有合成 `memz_app` 角色），以及可选的 `CHROMIUM_PATH`。测试不重置入口数据库：仅创建、使用并删除自己命名的随机库。在同一浏览器文档中，先实际提交来源，再故意丢掉已经收到的 200 回复；正常停止并在同一端口重新启动实际 CLI 后，验证旧 cookie 的 401、保留草稿/原键、人工同账号重登、重新核权及人工同键重放。八表指纹和来源/审计/回执计数独立核对无重复，另一账号有真实 403 控制。故意丢回复是明确的合成故障，不是任意真实网络故障或生产身份认证证明。

该集成有 64 个 HTTP、8 MiB 声明范围内应用字节、10 分钟工作和独立 1 分钟清理边界。字节覆盖父进程 SQL 参数/结果、CLI 输出和 HTTP 正文；不包括服务内部 PG、wire、浏览器控制协议、文件 IO 或堆分配。结果写入 `artifacts/session-recovery/run-*/report.json`，保留实际 runtime、源码哈希、dirty 状态、检查结果与清理状态。Node 22/24 CI 分别运行并归档；成功须以对应报告及 CI 为准。

`test/responsive-experience.js` 另在 320/390px 实测恢复区的长错误换行、可访问密码标签、Tab/Enter、双击单请求及编辑草稿时焦点/光标不被恢复流程抢走；API 为明确合成回执，不能代替上面的真实重启集成。
