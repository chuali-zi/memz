# 版本历史的有界读取

## 证据与范围

事实分页接入后，侧栏仍会下载全部修订。2026-11-04 在随机临时 PostgreSQL 16.15 数据库用固定合成语料、2000条填充事实复现：项目1有2007条修订，历史数组342028字节，候选数组510006字节（2009条），来源数组364字节（4条），审计数组12893字节（100条）。侧栏完整响应865352字节。数组大小不含属性名与其他JSON结构。

本阶段独立读取历史，页面每页25条。省略历史后的侧栏523313字节，历史第一页4572字节，两者合计527885字节；初次历史DOM从2007条限制为25条。以上仅为未压缩UTF-8 JSON字节数，不是HTTP头、网络带宽、SQL耗时或吞吐量。上述为历史分页阶段测量；后续[候选分页](candidate-pagination.md)已进一步减少候选读取，来源也已[独立分页](source-pagination.md)。

复现：设置测试管理员 `EVALUATION_DATABASE_URL`，运行 `EVALUATION_FILLER_COUNT=2000 npm run eval:retrieval`。报告 `contextScale` 保存各数组行数/字节数、旧侧栏、新侧栏、历史第一页和合计字节数；评测同时核对其余字段完全一致、第一页等于旧历史前25条。默认200规模也由CI执行。此次2000档原始报告位于工作区 `artifacts/history-scale-2000.json`，包括环境和源码校验值；正式引用应附同次报告，不能混用不同运行耗时或时间戳。

## 接口契约与兼容

`GET /api/projects/:p/history?limit=25&before=123` 返回 `{role,history,next_before}`。每条修订含 `id,subject,predicate,version,value,source,created_at`，按修订ID从大到小读取；旧聚合历史字段原样保留，不增加ID。`limit` 默认25、范围1–100；`before` 可省略，或为1–2147483647的十进制整数，表示排除该ID及更新编号。无后续页时 `next_before=null`；否则传回该值取下一页。重复、空或越界分页参数400，未登录401、非项目成员403。每页重新检查角色及RLS，使用只读REPEATABLE READ事务，多取一行判断是否还有下一页。

原 `/data` 缺省与 `include_history=true` 保持全部历史；可选 `include_history=false` 跳过历史SQL并省略history字段。可和 `include_facts=false` 组合；其他字符串或重复参数400。没有迁移或删除历史数据。

## 页面行为与一致性边界

工作台现并行读取审计、事实第一页、历史第一页、候选第一页及来源第一页；各请求不是共同快照。历史有独立游标栈、请求代次、加载/错误/空结果状态，较新一页、较旧一页和刷新历史按钮。刷新历史仅重读历史第一页，整页刷新或写入成功则重置事实与历史。旧请求不能覆盖后发刷新。加载时清空历史并禁用翻页；失败保留事实区且允许重试。页码状态可被辅助技术播报，键盘翻页后焦点移到历史标题；没有声称完成全面可访问性审计。

倒序游标避免新高ID修订把既有较旧页向后推移。新修订需刷新第一页查看；编号顺序不代表事务提交时间，晚提交的较低ID仍可能在后页出现，因此并不是跨页共同快照或严格时间点导出。行数限制不等于字节绝对上限或固定SQL成本，没有新增索引或宣称索引优势。

## 从历史版本查看原始依据

历史分页响应每行兼容新增fact_id（原id仍为修订ID，游标语义不变）。页面以fact_id和该行version请求既有的版本溯源接口，显示当时的来源ID、完整原文、修订/候选及提议/批准用户ID。读取旧版本不会改写当前事实；来源正文仅作为不可信数据展示，不执行。

每行按需加载，支持收起、重新展开和失败重试；项目切换或行已移除时，晚到响应不会写入新界面。仍由服务端验证项目权限，角色允许阅读不等于允许审批。浏览器演练在15号v2已生效后从历史展开20号v1，核对旧来源ID和正文、注入503后恢复及当前v2不变。24-mobile-history-provenance.png为实际窄屏取证。
