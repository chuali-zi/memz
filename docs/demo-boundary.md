# 默认运行与权限边界

Memz使用固定公开演示账号，默认Node进程绑定127.0.0.1，Compose数据库映射也绑定127.0.0.1。它不是多用户生产认证系统，不应公开到外部网络。数据库RLS的前提仍是可信服务端以非owner、非超级用户、无BYPASSRLS角色设置事务局部身份。

## 本次复现与修复

旧登录校验只比较Origin与请求Host。测试向本机随机端口发送原始HTTP，Host设为synthetic-demo.invalid、Origin设为http://synthetic-demo.invalid，并使用公开演示凭据，实际返回200。域名只用于本机请求头，没有DNS查询、外部主机访问或真实凭据。

现在所有请求（包含静态页面）在JSON解析和会话处理前校验Host。只允许localhost、127.0.0.1、[::1]字面量，以及可选1–65535端口；其他值返回403和固定说明“仅支持本机演示地址”。不以X-Forwarded-Host或X-Forwarded-Proto放宽此限制。默认CLI仍只监听IPv4回环地址，不因为允许[::1]头部而自动开启IPv6监听。

正常本地浏览器及Node客户端保持兼容；登录Origin仍必须与实际请求协议和Host匹配，缺省Origin的非浏览器客户端仍可使用演示账号。会话cookie、CSRF、角色审批和项目RLS没有因此取消或替代。自定义域名、公开反向代理不在默认支持方案内。

## 实际验证与限制

request-body.test.js使用Node原始HTTP确保Host确实发送到本机服务，覆盖匹配外部Origin、伪装本地域名后缀、转发头、已有会话、静态页面、非法端口，以及合法本机Host的登录/退出/CSRF流程。拒绝测试将数据库连接替换为失败哨兵，确认这些拒绝路径不访问数据库；完整PostgreSQL与真实浏览器回归另行验证原权限和演示链路。

Host校验是请求地址边界，不是身份认证：能自行构造HTTP请求的本机进程可以填写允许的Host；知道公开演示账号的人也能登录。它不提供网络攻击防护、速率限制、生产会话存储或数据库凭据泄漏防护。不能以本次回归推断生产级安全，也不能把仅绑定回环地址等同于所有浏览器访问场景都已受保护。
