# 默认运行与权限边界

Memz使用固定公开演示账号，默认Node进程绑定127.0.0.1，Compose数据库映射也绑定127.0.0.1。它不是多用户生产认证系统，不应公开到外部网络。数据库RLS的前提仍是可信服务端以非owner、非超级用户、无BYPASSRLS角色设置事务局部身份。

## 本次复现与修复

旧登录校验只比较Origin与请求Host。测试向本机随机端口发送原始HTTP，Host设为synthetic-demo.invalid、Origin设为http://synthetic-demo.invalid，并使用公开演示凭据，实际返回200。域名只用于本机请求头，没有DNS查询、外部主机访问或真实凭据。

现在所有请求（包含静态页面）在JSON解析和会话处理前校验Host。只允许localhost、127.0.0.1、[::1]字面量，以及可选1–65535端口；其他值返回403和固定说明“仅支持本机演示地址”。不以X-Forwarded-Host或X-Forwarded-Proto放宽此限制。默认CLI仍只监听IPv4回环地址，不因为允许[::1]头部而自动开启IPv6监听。

正常本地浏览器及Node客户端保持兼容；登录Origin仍必须与实际请求协议和Host匹配，缺省Origin的非浏览器客户端仍可使用演示账号。会话cookie、CSRF、角色审批和项目RLS没有因此取消或替代。自定义域名、公开反向代理不在默认支持方案内。

## 实际验证与限制

request-body.test.js使用Node原始HTTP确保Host确实发送到本机服务，覆盖匹配外部Origin、伪装本地域名后缀、转发头、已有会话、静态页面、非法端口，以及合法本机Host的登录/退出/CSRF流程。拒绝测试将数据库连接替换为失败哨兵，确认这些拒绝路径不访问数据库；完整PostgreSQL与真实浏览器回归另行验证原权限和演示链路。

Host校验是请求地址边界，不是身份认证：能自行构造HTTP请求的本机进程可以填写允许的Host；知道公开演示账号的人也能登录。它不提供网络攻击防护、速率限制、生产会话存储或数据库凭据泄漏防护。不能以本次回归推断生产级安全，也不能把仅绑定回环地址等同于所有浏览器访问场景都已受保护。

## 数据库空闲连接中断后的恢复

连接池原先没有处理空闲连接的 error 事件。在隔离 PostgreSQL 测试库中终止测试子进程自己的空闲后端连接，应用实际以退出码 1 结束。现在监听该事件，只输出固定诊断；pg 已移除损坏连接，后续请求重新获取连接。应用进程和已有内存会话保持存活，不自动重放业务写入。

`test/connection-recovery.test.js` 用唯一 application_name 定位自己的后端，不终止其他应用连接。实际验证关闭连接后原只读会话仍能读取相同项目、事实及指定版本来源，另一项目仍返回 403，日志不包含连接对象或凭据。通过 `npm run test:system:evidence` 在临时数据库运行，不能直接指向现有业务库。

此测试只证明空闲连接被关闭后可建立新连接，不证明持续数据库停机、活动事务中断或网络分区下的高可用。活动写入不会自动重试；响应丢失时应先核实结果，并在支持幂等键的创建接口复用原键。刷新页面不会持久保存尚未提交的表单或客户端幂等键。进程重启仍会清空内存会话，需要重新登录；数据库中的已提交记录保留。

## 独立 PostgreSQL 停机与恢复演练

`npm run test:outage` 需要 Linux 本机 Docker 套接字和 postgres:16 镜像。脚本创建独立容器、随机回环端口和全新合成数据；仅停止、启动和删除它自己创建的容器，最后删除其匿名卷，不使用 DATABASE_URL 指向的现有库。CI 同样运行，并上传 outage-evidence。报告为 artifacts/outage-report.json。

实际停机复现：原读取返回 500“请求无法处理”。现在已识别的连接拒绝、连接重置、超时、PostgreSQL 关闭/恢复及连接异常返回 503。读取提示稍后重试；写入提示结果可能不确定，不能把错误状态当成未提交证明。其他错误仍走原有处理，不统一声称可重试。

演练使用真实 HTTP 和 public/app.js 的创建逻辑：停机时不会自动重放；数据库启动后原会话继续读取，同一创建意图保留幂等键。另在真实提交后人为丢弃响应，期间再次停机，再恢复并用同一键重试，验证返回原记录 ID 且数据库中只有一条来源。此“响应丢失”是明确注入的合成故障，不是模拟所有网络故障。跨项目访问仍被拒绝。

创建重试必须保持原路径、内容、账号和幂等键；修改内容是新意图。审批等非创建操作应重新读取状态和版本后决定下一步，不盲目重复。测试没有证明活动事务在任意中断点的结果，也没有覆盖长时间网络黑洞、自动故障转移或生产高可用；目前没有自动重试循环，也没有跨页面刷新保存幂等键。

停机演练还会启动真实 Chromium（先执行 `npx playwright install --with-deps chromium`，或设置 CHROMIUM_PATH），在390px视口验证来源读取失败、写入不确定、输入保留、恢复后人工重试，以及真实提交后拦截丢弃响应的场景。四张截图随 outage-evidence 上传；这是独立演练证据，不计入常规31张UI截图。已检查写入提示可见、无横向溢出。创建失败提示现在说明保持本页和内容不变后再次提交，页面负责复用请求；不要求普通用户自行管理幂等键。不自动重试，不承诺刷新或改写内容后仍保持原关联。
