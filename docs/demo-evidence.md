# 浏览器演示证据与复现

截图来自真实 Chromium 访问 Express + PostgreSQL，不是设计稿。使用公开合成账号/数据，不调用模型。自动流程仅证明列明的演示路径，不能替代全部权限、数据库或生产安全测试。

## 独立运行（推荐）

先初始化测试 PostgreSQL（创建演示应用角色），不必启动应用，不重置已有演示库：

```sh
# 选择系统Chromium；不设置CHROMIUM_PATH则使用Playwright下载的Chromium
UI_TEST_DATABASE_URL=postgres://postgres:postgres_demo_only@127.0.0.1:5432/memz \
CHROMIUM_PATH=/usr/bin/chromium npm run test:ui:evidence
```

没有系统浏览器时先运行 `npx playwright install --with-deps chromium`。CI 使用锁文件对应的 Playwright Chromium，依赖安装包含文泉驿中文字体，随后用fontconfig检查中文字体可用；不额外重复下载字体包。

此命令需显式测试管理员连接，只创建和删除随机 `memz_ui_*` 临时库；应用连接为memz_app，服务监听127.0.0.1随机端口。评测不修改管理员连接指定的库，不要求停止现有3000端口服务。进程被强制终止时可能残留临时库，需要核对后清理，不应批量删除不明数据库。不要提供生产管理员凭据。

原 `npm run test:ui` 仍用于手动启动的3000端口演示，要求初始种子状态，且会修改该演示库。它不能代替保留数据升级命令。

## 会话失效恢复回归

真实浏览器用有效CSRF调用注销，使服务端会话失效但保持工作台页面；刷新确认401后，点击切换账号应回到登录页并能再次登录。修复前此流程停留在工作台并持续401；现在仅对注销401允许回登录。单元回归同时验证403、503和网络失败不被吞掉。结果记录在UI报告checks.sessionRecovery中，属于会话失效等效场景，未声称测试实际等待8小时或真实进程重启。截图仍为原20项，此检查用交互断言取证。


## 首次项目列表加载与恢复

新增登录后项目列表503、恢复时空列表、旧失败延迟返回的注入场景。修复前，刷新工作台请求null项目路径，不能加载事实；修复后刷新会重新获取项目列表。无项目时写入按钮禁用、分页/搜索不发送无效项目请求，明确提示切换账号或重试；最新请求成功后晚到的旧失败不覆盖状态。恢复后继续执行完整批准与权限流程。

这些是浏览器拦截层的明确故障注入，不是数据库实际宕机或真实用户研究。页面成功状态仍通过真实应用和临时PostgreSQL读取验证。结果在report.checks.projectRecovery中，20张既有截图不新增故障图；失败运行目录中的failure.png仅是缺陷复现证据。材料校验器要求该检查存在且一致。
