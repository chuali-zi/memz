# 完整操作审计分页

原页面只显示 `/data` 中最近100条审计，没有更早记录入口。独立数据库回归构造超过100条审计，确认旧聚合仍限100；新界面可逐页访问初始化记录。修复不增加或修改数据库记录、约束与迁移。

`GET /api/projects/:p/audit?limit=25&before=<id>` 按ID降序读取，默认25、最大100，返回 `{sourceTextIsUntrusted:true,role,audit,next_before}`。before必须是正int32；省略代表最新一页。服务器多取一条判断续页；非成员403，只读成员可查，身份和RLS仍在只读快照事务内校验。

兼容保留 `/data` 默认最近100条审计；可选 `include_audit=false` 跳过查询并省略字段。新页面独立加载审计，每页25条，可上一页、下一页、刷新，展示记录ID、操作、原详情、操作者和时间。断网清空旧结果、禁用翻页并提示刷新；异步响应按请求代次及项目丢弃。翻页后焦点回到审计标题。

这是记录ID游标，不是全历史一致快照或提交时间排序：普通新增高ID记录不会移动已加载游标后的记录，刷新回最新页；并发事务可以较晚提交较低ID记录，因此跨页不能承诺永久无遗漏。审计不可由应用更新或删除，但数据库管理员仍有维护权限。没有性能优越性或生产合规审计声明。

验证：test/pagination.js 的超过100条完整ID对照、翻页中新增、viewer访问、跨项目拒绝、无效游标和旧接口兼容；test/ui.js 真实浏览器遍历至初始化记录并模拟网络失败恢复。截图31和报告使用隔离临时PostgreSQL、公开合成账号，不触及既有演示库。
