# 显式开启 MCP 字段问句读取

默认 MCP 工具清单保持不变：只读配置仅提供 `memz_read_context`，开启候选提交后仍按原顺序提供 `memz_read_context`、`memz_submit_proposal`。

需要固定模板字段问句时，由操作者在宿主的 `memz.env` 中显式设置 `MEMZ_MCP_ENABLE_LABEL_CONTEXT` 为字符串 `"1"`，重启该 MCP 进程。只接受 `"0"`、`"1"` 或未设置，默认关闭。开启后在原清单末尾增加 `memz_read_label_context`；它不会开启候选提交或授予项目权限。配置生成器始终显式输出 `"0"`，避免父进程的开关改变生成的默认清单；本功能不自动修改宿主设置。

工具调用示例：

```json
{"name":"memz_read_label_context","arguments":{"question":"晨桥服务的交付时间是什么？","maxOutputBytes":32768}}
```

示例主体、字段必须实际存在于所选项目的已批准事实中。只接受 `question` 和可选 `maxOutputBytes`。问句必须是至多210个UTF-16单位的非空、合法Unicode文本（100×2标签＋5连接词＋4问尾＋1可选问号）；先限制原始长度再trim，外围空白占预算，代理对占两个单位。此增强仅适用于显式v2工具，原read.query上限200与默认v1不变；stdin16KiB、metadata512和正文预算不变。输出预算为2048–32768字节，默认32768。项目、地址和演示账号固定于进程配置，调用参数不能传入身份、标签目录、精确选择器、gold、来源、协议、查询模式、分页、期限或取消信号。

内部固定使用 `metadata_exact_v2`：在同一登录会话中取得完整授权标签目录，再用固定问句模板生成字面主体/字段选择器，通过精确接口读取一个已批准事实及完整证据，最后退出会话。正常匹配为登录、标签、精确读取、注销四个 HTTP 请求；策略拒绝为三个。最多接受 512 个标签；超过上限只返回 `needs_scope / SCOPE_TOO_LARGE`，不会使用前缀目录、分页拼接、关键词回退或模型调用。未知、模糊或不支持的问题保留明确的 `no_match`、`needs_scope` 或 `unsupported` 状态，不会编造答案。

结果为一份 `memz-label-context-v2` JSON，保留 `memz-exact-context-v1` 的精确选择器、版本、修订、候选、批准者及完整来源字典。规划目录和精确证据来自两次独立只读事务，**不共同冻结**；两个阶段之间的新批准可能使返回版本更新，权限撤销会使后续读取失败。`sourceTextIsUntrusted` 始终保留，来源中的指令仍是数据；工具注解不替代宿主授权或防提示注入措施。工具没有审批、来源写入或任意 HTTP 能力，HTTP 登录、CSRF、角色和数据库隔离仍照常执行。

预算覆盖完整 JSON 结果，包括来源原文与回执；单位是 UTF-8 JSON 字节，不是 token。无法容纳完整证据时返回 `OUTPUT_BUDGET_TOO_SMALL / read_failed`，不截断原文或返回部分成功。内部标签响应允许最多 1 MiB，合法的 512 条转义标签可能超过 MCP 单条发送上限；目录不会直接透传到 stdio。最终只发送预算内的结果，原 256 KiB 全局保护保持不变。

两种读取工具均向模块传入 SDK 的本次调用取消信号，取消会中止实际登录/读取及正文消费。已经取得有效会话后仍尝试有界注销；取消或断连后宿主可能收不到回执，不能据此声称服务端会话或事务已经撤销。未取消时 BUSY、握手、旧工具输入及结果结构沿用原合同。

`node --test test/mcp-label-context.test.js` 使用真实官方 SDK、stdio 子进程和回环 HTTP 合成服务验证开关矩阵、参数隔离、完整证据、目录和输出字节边界、错误后的连接恢复及两类读取的取消/断连。`MIGRATION_TEST_DATABASE_URL=明确测试管理员连接 node --test test/mcp-label-context-postgres.test.js` 在独立随机数据库验证 512/513、项目隔离、两阶段间撤权、篡改回执、完整原文、转义目录和业务表未修改，并删除本次临时库；不指向生产。均不调用模型、不安装或修改真实宿主配置。
