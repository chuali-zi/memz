# 可复现的合成检索评测

目标是验证当前已批准事实的关键词检索语义，并为后续性能优化保存可比较的测量。所有数据均为合成样例；这里没有真实模型、语义召回、赛事得分或生产负载结论。

## 运行与安全范围

先按 README 初始化本地测试 PostgreSQL，再运行：

```sh
EVALUATION_DATABASE_URL=postgres://postgres:postgres_demo_only@127.0.0.1:5432/memz npm run eval:retrieval
```

必须显式提供测试管理员连接，无默认值。脚本在同一实例创建随机命名的 `memz_eval_*` 数据库，仅在该临时库初始化 schema、导入语料、运行服务并删除临时库；不修改连接指定的数据库或重置现有卷。初始化过的实例须已有公开演示角色 `memz_app`。管理员连接只用于临时库生命周期和初始化；语料审批、HTTP 检索使用应用角色。不要使用生产管理员连接。

报告写入被 Git 忽略的 `artifacts/retrieval-report.json`。失败返回非零状态，正确性失败仍生成报告；连接或初始化失败时可能没有报告。CI 运行同一脚本，将报告上传为 `retrieval-evaluation` artifact。若进程被强制终止，临时库可能残留，应按报告执行环境人工核对后清理，不能批量删除不明数据库。

## 数据与用例

固定数据定义位于 `evaluation/retrieval-cases.json`，标识为 `memz-synthetic-retrieval-v1`。包含初始合成事实、5 项针对性事实、200 项编号事实、1 项其他项目事实，并保留旧修订、待审和驳回候选。正常导入结果为 207 条事实、208 条修订、210 条候选、5 条来源。第二项目的事实不应泄漏给第一项目。

19 个用例逐一比较 HTTP 状态及完整 `(主体,属性,值)` 多重集合，不仅检查是否包含目标结果：

- 中文主体、属性、当前值和大小写不敏感匹配。
- `%`、`_`、SQL 样式字符串与 HTML 文本作为字面量检索。
- 旧修订、待审、驳回、来源正文和其他项目内容不进入当前事实结果。
- 无匹配、单条命中、空查询返回全部当前事实。
- 只读用户可检索、第二项目可查自己的事实、跨项目请求得到 403。

来源、候选和历史仍可在接口相应字段中展示；这里验证的是 `facts` 搜索结果，不能把“未进入当前事实”理解成从所有响应字段隐藏。

## 测量方法与解释

每例先热身 2 次，再测量 10 次，串行发送 localhost HTTP 请求。计时包括服务端完整项目聚合读取、HTTP 传输和客户端 JSON 解析，不是单条 SQL 执行时间。每次请求（含热身）均检查正确性；授权拒绝用例也单独记录耗时，不混成检索吞吐量。

报告包含每例原始毫秒样本、中位数、nearest-rank p95、最小/最大值，Node/PostgreSQL/CPU 信息、Git 提交与工作区脏状态，以及数据文件、服务端、评测器的 SHA-256。耗时没有通过阈值，避免不同运行器导致随机失败；正确性是 CI 的硬性条件。

这是小语料、热缓存、单客户端的观察基线。比较两次报告须核对语料/实现校验值、环境、正确性和采样方法；10 个样本的 p95 等于最大样本，不宜过度解释。它不能支持并发容量、生产延迟、索引优劣或语义检索质量结论。后续应先扩展受控数据规模和负载，再决定索引、分页或响应裁剪。

## 响应规模与分页验证

报告 schemaVersion 2 增加 fillerCount、原响应 UTF-8 字节数和返回行数，以及每例分页完整遍历的页数、最大页行数、首/总字节数。分页使用相同黄金结果验证但不计时；原 HTTP 耗时仍仅指聚合接口。默认填充200，可通过 EVALUATION_FILLER_COUNT 设置200–5000。测量结果和快照边界见[游标分页](bounded-retrieval.md)。

报告contextScale另记录来源/候选/历史/审计数组规模，以及省略历史的侧栏与历史第一页合计字节数。固定种子下核对其他字段不变、历史第一页等于原聚合前25条；不进行新旧请求耗时比较。详见[历史分页实测](history-pagination.md)。

报告candidateScale增加来源/审计响应、候选第一页及与历史第一页合计的JSON字节数（不含事实页），并核对旧候选前25条及保留字段。测量与限制见[候选分页](candidate-pagination.md)。
