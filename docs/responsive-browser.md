# 响应式长文本与键盘回归

`test/responsive-experience.js` 使用真实 Chromium 加载 `public/` 的静态 HTML、CSS 和脚本；API 是明确的合成回执，不访问数据库、模型或外部服务，不代表生产认证测试。

运行：

```sh
node --test test/responsive-experience.js
```

默认使用 Playwright bundled Chromium；已有系统 Chromium 的环境可显式设置 `CHROMIUM_PATH=/usr/bin/chromium`。测试有自己的浏览器、HTTP server 和有界清理，不依赖共享浏览器。

## 复现与修复

测试使用 300 字项目名、1024 字符以上的显示名、150 字符来源标题、4000 字符来源内容、1000 字符事实值，以及 5000 字符以上的连续错误文本；均在当前整份响应 1MiB 限制内。

修复前，长显示名撑开页头，连续错误文本撑开 `#notice`。真实 Chromium 的文档宽度如下；每行是相应独立视口，单位 px：

| 视口 | 登录后修复前 | 显示错误后修复前 | 修复后两种状态 |
| --- | --- | --- | --- |
| 320 | 9813 | 47238 | 320 |
| 360 | 9813 | 47238 | 360 |
| 768 | 9827 | 47238 | 768 |
| 1280 | 9853 | 47238 | 1280 |

页头现在允许随文本增高，账号区域允许缩小并断行，全局提示允许在连续文本内换行。没有隐藏横向溢出、裁剪正文或缩短字段。原有事实/来源 `.entry` 的换行规则已通过检查，保持不变；项目和来源使用原生下拉框，完整 option 文本及选中值保留。

## 验证边界

四个视口都检查登录后及错误恢复入口可见时的 `documentElement.scrollWidth`、关键元素边界和完整文本值。测试用真实 Tab 顺序覆盖当前项目、检索输入/按钮、来源选择、候选值、添加来源、来源操作及切换账号，验证水平可达和可见焦点；Enter 可展开来源全文，并通过添加来源链接把焦点移到标题输入框。错误后仍可再次聚焦切换账号入口。

这些是合成长文本的桌面 Chromium 回归，不声称覆盖所有移动设备、原生下拉弹窗渲染或屏幕阅读器。既有 `test/product-experience.js` 的 82 项继续独立保留；本文件新增 4 项响应边界回归。
