# 浏览器响应资源边界

页面所有 API 请求共用固定的 15 秒总期限，覆盖请求和完整正文读取；每份正文另有固定 1 MiB（1048576 字节）上限。按浏览器 Fetch 暴露的正文 bytes 计数，包含 JSON 结构与文本编码，不按 JavaScript 字符长度或不可信 Content-Length 判断。压缩响应按浏览器解压后的正文计数；不是项目名称等单个字段的新增长度限制。

页面逐块读取，只有正文完整结束且未超限，才以严格 UTF-8 解码并解析 JSON。分块多字节字符可完整拼接；合法的 U+FFFD 字符不因外观像替代字符而被拒绝。超限、损坏 UTF-8、无效 JSON 和未结束正文均不会裁剪成成功结果。之后继续执行各接口自己的回执绑定校验。

出错时主动 AbortController 中止真实 Fetch，再尽力取消 reader 并释放锁；取消或释放异常不能覆盖原错误，也不输出原始流错误细节。15 秒和字节上限没有可由调用参数覆写的生产开关。HTTP 中止不保证撤销服务器已经执行的写入，也不保证取消服务器 SQL。

确定拒绝沿用原合同：只有完整读取、解码、解析且 error 为字符串的 HTTP 4xx 回执才赋予错误 status，并结束对应创建意图。403/409 头部本身不被当作完整应用回执；其正文若损坏、超限或不完整，创建结果仍按无法确认处理。有效 403 主错误即使 reader 清理异常也保持原状态与业务文案。

无法确认的创建保留草稿和当前页面内的幂等键；不自动重放。用户恢复后保持相同路径与内容，手动提交复用原键。刷新页面仍会丢失未持久化的意图，不承诺跨刷新或跨账号恢复。读取失败保留该列表最后成功页和翻页状态；各列表仍是独立请求。

独立 Chromium 回归使用本机 HTTP server 和真实浏览器 Fetch：快速超大完整 JSON、损坏 UTF-8、超过上限但不结束的流，并以服务端 close 事件验证实际取消连接。另以明确标注的 reader 清理故障注入验证主错误不被覆盖；没有以自定义假 fetch 代替这些连接检查，不调用模型或真实数据库写入。
