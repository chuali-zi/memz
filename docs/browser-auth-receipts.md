# 演示页面的登录与退出回执

当前服务端成功登录返回 `{name,csrf}`，成功退出返回 `{ok:true}`。页面只有完整读取并验证这些回执后，才接纳对应的成功界面状态。沿用固定 15 秒及 1 MiB 正文上限、严格 UTF-8；没有为认证路径增加 JSON fallback。

登录要求 name 为非空、合法 Unicode 字符串，csrf 为非空 graphic ASCII（U+0021—U+007E）字符串。CSRF 作为不透明值原样使用：不 trim、不解析、不固定为当前服务端生成的 48 位 hex。这样既接受当前实现，也接受不含空白或控制符的其他 opaque 格式，避免 HTTP header 规范化改变值或无法传输。没有新增任意 token 字段长度限制；整份响应仍受已有资源上限限制。

坏登录回执显示固定错误，不回显字段值，也不修改页面内 csrf、身份显示或登录/工作台显隐，不发项目请求；表单保留以便重试。未知附加属性不显示。有效 CSRF 仅留在当前页面的 JS 内存并用于请求头，不写入 DOM、浏览器存储或日志。页面拒绝成功状态不代表能够撤销 HTTP 已设置的 Cookie 或服务器已创建的会话。

退出必须明确收到 own `ok:true`。空对象、错误类型等成功状态码回执不被当作确认，不刷新页面、不丢弃当前草稿；固定错误说明“尚未确认退出”，不声称服务器未执行退出。按钮单次在途、忙碌时禁用，失败后恢复可重试。若焦点因禁用按钮落到 BODY，仅在同一工作区时恢复按钮焦点；用户已主动聚焦草稿时不抢焦点。

完整且已知的 401 仍按会话已经失效处理，刷新回登录页。损坏或未完整确认的响应不伪装成已知 401。有效退出和已知 401 的整页刷新仍会丢失未持久化草稿；没有增加跨账号或跨刷新恢复、生产认证、模型调用或自动审批。

独立 Chromium 回归使用受控合成响应验证坏登录/退出、原样 header 传输、敏感字段不进入 DOM/存储、重复触发保护、焦点及草稿保留、有效重试和 401 路径；真实会话与权限仍由独立服务端/数据库回归覆盖。
