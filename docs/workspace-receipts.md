# 页面项目与工作台回执

页面仍是公开账号、合成数据的本机演示，权限由服务端会话与项目检查决定。浏览器校验回执用于避免错误的页面状态，不是生产认证或额外授权机制。

`GET /api/projects` 返回数组。页面在完整检查每项的正整数项目 ID、字符串名称、owner/member/viewer 角色及 ID 唯一性后，再用暂存节点一次填入项目选择框。名称允许空字符串和长文本，与当前数据库字段合同一致；不增加虚构的长度限制。未使用的附加属性不读取、不显示。非法 ID 不会进入后续 API 路径。

重新读取可访问项目是一次新的访问边界：先移除旧项目、旧列表操作和已选依据，防止把上一身份的项目继续展示；即使新列表为空、失败或形状错误，也不恢复这些旧交互。候选和来源表单的草稿文字保留。合法 JSON 坏列表会显示格式错误，不会部分填入已通过的前几项；可用“刷新工作台”重新读取。

页面读取工作台时显式将五个 `include_*` 参数均设为 `false`。当前服务端响应为 `{ sourceTextIsUntrusted: true, role }`，没有可用于再次绑定的项目 ID 字段。页面要求这两个必需字段有效，只保存它们；未使用的附加属性不会渲染或保存在工作台数据中。坏回执不会被当作成功角色状态，也不会启用依赖该状态的来源保存、候选提交和模拟按钮，或把尚未恢复的工作台错误清除。草稿保留，成功重试后才清除属于本次工作区的错误提示。

五类列表仍独立、并行读取并分别验证回执。合法的列表响应可以在工作台 bootstrap 失败时更新自己的区域；独立候选列表的审批入口依据它自身的角色回执生成，提交时仍由服务端核查。页面不提供跨 HTTP 请求的共同快照或整页原子提交，也不把旧项目内容当作新项目数据。

独立浏览器验证入口：

```sh
CHROMIUM_PATH=/usr/bin/chromium node --test test/product-experience.js
```

不设置 `CHROMIUM_PATH` 时使用已安装的 Playwright bundled Chromium。用例采用明确合成的受控 API 响应，不调用模型或现有数据库；真实数据库和真实权限链路由独立系统/UI 回归验证。
