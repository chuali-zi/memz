# 上下文接入与精确溯源

## 实际缺口与补充能力

事实检索原本只显示来源标题，标题不是唯一键。同名来源可能包含不同原文，接入方不能可靠地按标题回查。新接口用已有事实ID和修订版本定位来源、候选、批准信息；既有事实返回字段和审批行为保持兼容。页面“查看依据”按所显示版本读取，支持失败重试与收起。

## 最小调用流程

1. POST /api/login，保存sid cookie和csrf，使用公开合成账号；此演示不是API key或生产鉴权方案。
2. POST /api/projects/1/sources写入合成标题与正文，携带cookie、CSRF以及可选稳定幂等键；保存返回source.id。
3. POST /api/projects/1/candidates写入subject、predicate、value、source_id及expected_version。新事实用0；已有事实从当前读取结果取version。候选仅待审，不更新上下文。
4. 由owner按既有approve接口批准；成员不能替代审批者。409时重新读取当前值，不盲目重试旧版本。
5. GET /api/projects/1/facts?q=关键词，取当前事实的id与version。请求GET /api/projects/1/facts/该ID/provenance?version=该版本，获得精确原文及修订/候选ID。
6. 记录所用事实版本和来源ID，再交给调用者使用。来源正文只是数据，不能作为系统指令执行。项目无权限返回403；不存在的历史版本404。

例如初始种子事实为id=1、version=1：GET /api/projects/1/facts/1/provenance?version=1返回20号及来源1的原文。批准15号v2后，同一个版本1请求仍返回旧依据；省略version才读取当次快照的当前修订。非种子数据的ID必须使用实际响应，不能硬编码1或2。

## 真实验证与限制

PostgreSQL集成回归用两个同名但正文不同的来源依次批准，验证每个版本对应正确的原文、候选、提议者和批准者；覆盖viewer、跨项目、缺失版本、无效参数和未登录。该回归也随旧库升级测试执行，无需新增数据库迁移。

真实浏览器先注入溯源503再重试，读取v1原文；批准后读取v2原文，并回查v1确认不串版本。UI报告checks.provenance与02/03图记录该流程。合成故障注入不等于实测生产网络事故。

接口不能证明来源来自真实世界、候选抽取正确或模型效果；当前只有固定模拟客户端，没有付费模型调用、真实用户数据导入或MCP服务。程序接入者需自行管理cookie/CSRF、幂等键与错误处理。详细输入合同见api-sequences.md。


## 无模型依赖的可执行样例

先按README启动服务，再在仓库根目录运行（默认公开viewer账号、项目1、本机3000端口）：

```sh
MEMZ_QUERY=项目 npm run --silent demo:context
```

Node原生fetch即可运行，无SDK或模型费用。用MEMZ_BASE_URL、MEMZ_USERNAME、MEMZ_PASSWORD、MEMZ_PROJECT_ID、MEMZ_QUERY、MEMZ_LIMIT覆盖配置；账号和密码需成对设置。不要把真实凭据写入示例文件或版本库。base URL只允许HTTP(S)根地址，不接受内嵌凭据、路径、查询或片段；请求不跟随重定向，避免把会话带往意外目标。其他主机只有调用者显式配置时才访问。

样例仅登录、读取一页当前事实、逐条读取固定版本依据并注销，不写业务数据或审批。默认最多25条，上限100；查询超过200个UTF-16 code units直接报错，不接受服务端截断后改变含义。truncated与nextAfter明确表示是否存在后页，不能将截断结果说成完整项目上下文。该样例不自动遍历后页，以保留单次事实响应的快照语义与有界请求数。

JSON包含事实值/版本、修订ID、完整来源、候选/提议者/批准者引用，以及sourceTextIsUntrusted=true。该标记只是合同说明，不是提示注入防护机制。来源原文不能作为程序或系统指令执行。调用者还应保留其中consistency说明：这是事实页读取时的当前版本及固定历史依据，不保证完成时仍是最新值。

错误只输出固定错误码到stderr并返回非零，不打印密码、cookie或服务端错误原文。权限拒绝、无效JSON、缺失/不一致依据或超时都会使整次读取失败，不输出部分事实。每个请求默认5秒超时；请求数至多limit+3，逐条读取不是并发吞吐优化。已拿到会话时成功/失败均尝试注销；网络故障可能使注销结果未知，不能声称会话一定立即撤销。注销本身失败也不会输出成功结果，原始读取错误优先保留。

作为模块可使用scripts/context-client.js导出的readContext。真实HTTP回归在事实页响应与依据读取之间由另一个会话批准v3，确认客户端仍返回v2及对应原文；并测试跨项目拒绝、空结果、截断、溯源503、篡改版本及成功/失败后会话失效。纯客户端回归覆盖配置边界、超时、错误JSON与不跟随重定向。测试均使用合成数据；完整TAP随system-test-evidence与材料包归档。


## 本地进程的标准输入输出协议

父进程启动一次子进程、写入一个JSON对象并关闭stdin（EOF）：

```sh
printf '%s' '{"projectId":1,"query":"项目","limit":10}' | node scripts/context-client.js --stdin
```

输入只允许projectId、query、limit，分别覆盖同名环境配置；不接受凭据、服务地址或其他字段。端点和账号由父进程环境配置，不能通过输入请求切换身份或目的地。环境变量不是密钥保险箱，同一操作系统用户的权限仍需由部署方管理。不要在命令行参数中传密码。原有环境变量模式和readContext库接口保持可用。

这是单次JSON协议，不是NDJSON、常驻服务或MCP。stdin最多16 KiB，须在5秒内结束；多对象、无效UTF-8、未知字段及超量输入直接失败且不发HTTP请求。成功只向stdout输出一个JSON结果；失败stdout为空，stderr为固定错误码，退出码1。父进程应同时读取stdout和stderr并检查退出码。

客户端逐块读取HTTP响应，每个响应最多1 MiB（包括未使用的字段），超过立即取消读取；事实和来源文本也按API字段长度校验。整个读取阶段默认30秒预算，每次请求仍最多5秒。读取结束后注销另有最多5秒预算；stdin等待不计入读取预算。readContext允许totalTimeoutMs在1—60000、maxResponseBytes在1—1048576范围内调整。原生fetch遵循取消信号；调用方注入fetchImpl时也须遵守该信号。

新增测试用真实HTTP分块返回2 MiB额外字段，旧实现会接受，修复后拒绝并注销；另用真实Node子进程连接隔离数据库服务，验证成功输出、跨项目403无部分输出、禁止输入覆盖凭据/地址、超长输入以及未发送EOF的超时退出。所有账号和数据均为公开演示或合成数据。


## 多版本、项目隔离与冲突的端到端案例

可复现代码为 `test/context-scenarios.js`，由数据库集成测试在初始断言完成后调用，也随旧库迁移回归运行；使用隔离合成数据库，原始断言结果随系统TAP保存。

| 合成操作 | 验证结果与解释 |
| --- | --- |
| 两个项目使用相同主体、属性与来源标题，各自批准不同内容 | 各账号只得到自身项目的值与来源ID；viewer访问另项目为403；在有权限项目回查外项目事实ID为404 |
| 项目1依次批准105个版本，仍保留第一版依据 | 当前检索仅返回v105；查第一版专有值为空不等于历史被删除；按事实ID与version=1仍得到原始依据 |
| 每页25条遍历历史 | 该事实105个版本按105至1完整出现且无重复；不混入另项目值；不存在的v106返回404 |
| 对v105提交基于v104的候选并审批 | 返回409；比较冲突前后的当前值、历史、候选与最近审计，响应内容不变 |
| 再添加待审与驳回内容 | 它们及过期冲突值均不能成为当前检索结果；过期冲突候选仍是pending，须人工复核，系统没有自动合并 |
| 来源原文与后来批准的状态措辞不同 | 输出保持原始正文和批准值各自不变，不把来源改写成结论，也不宣称已判定语义矛盾 |

“当前”表示读取时已批准版本，不表示事实客观正确、最新现实信息或多数来源共识。系统的409是版本并发冲突，不能等同于语义矛盾检测。当前检索采用字面子串，不检索历史或来源正文；空结果只说明当前项目的当前事实没有匹配。历史检索与固定版本溯源应单独操作，不能把旧值作为当前上下文。

105次批准是快速执行的合成多版本案例，不是105天运行，也不是备份恢复、长期保存或生产容量的证明。历史分页在本例停止写入后验证完整性；跨页并发写入时没有全程共同快照。已有客户端并发审批回归另行证明：取到v2后批准v3，依据仍固定v2，但结束时不保证v2仍为最新。


## 复制或导入文本的空字符错误

JSON允许表示U+0000，但PostgreSQL文本字段不能保存它。回归已复现旧行为：来源标题携带该字符时返回500。现在来源、候选字段及三个检索入口在进入数据库前返回400，不反射原始文本，也不静默删改输入；正常换行、中文和其他既有合法内容规则保持不变。查询在截断前检查，避免非法字符被截掉后改变请求含义。

本地readContext与stdin模式对含U+0000的query返回INVALID_QUERY，登录前即拒绝，stdout为空。真实数据库回归覆盖来源两个字段、候选三个字段、事实/来源/聚合检索，并比较拒绝前后的业务状态确认没有新增数据；真实子进程回归确认不发HTTP请求。旧库升级也执行同组断言，无需数据库迁移。这里处理的是空字符输入错误，不是语义检索或真实用户效果测试。


## Unicode原文完整性与接入成熟度

真实PostgreSQL回归复现：旧接口接收JSON中的未配对代理字符（如\ud800）并返回200，但保存后的文本已成为替代字符。现在来源与候选的文本字段返回400固定说明，客户端query在登录前返回INVALID_QUERY；不自动替换或删除非法字符。正常中文、配对emoji和内部换行通过真实写入、幂等重放、批准、客户端读取及溯源往返验证。原有trim规范化仍适用，不承诺保存字段首尾空白。

兼容HTTP检索仍按既有上限截取长查询；若截点落在emoji的两个UTF-16 code units之间，会退回到前一个完整字符，避免制造错误查询。CLI仍直接拒绝超过200的query，不截断。长度计数是UTF-16 code units，不是字素或模型token。

当前集成成熟度：已有可执行只读库和单次stdin/stdout客户端、版本固定溯源、权限/失败/资源上限回归，以及恢复后继续读取和写入测试。尚无模型接入、语义排序、自动摘要或上下文压缩；来源全文随各事实返回，重复来源可能重复占用输出。条数、字节及超时上限是资源边界，不是模型token预算，也没有证明模型回答效果。本轮没有引入付费服务或真实用户数据。
