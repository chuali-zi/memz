# 当前首次安装的独立集成

`node test/first-run-cluster.js --execute` 是显式、会创建资源的测试，不加入默认核心测试。实际执行前必须确认本机 Docker 可用，且已有缓存 `postgres:16`；它不下载镜像、不安装依赖，也不使用已有数据库或应用角色。可选 `FIRST_RUN_CLUSTER_OUTPUT` 指定全新的报告目录。

测试生成唯一 Compose 项目、空命名卷、internal bridge 网络和随机 loopback PostgreSQL 端口。启动前同时核对项目标签及精确容器/卷/网络名均不存在，避免复用无标签同名对象。配置以当前 `compose.yml` 的已解析服务为依据，保留镜像、公开合成环境值和健康检查；替换项目资源及端口，并增加初始化观察脚本。该脚本以独立可执行进程在原 schema 前只读检查 `memz_app` 不存在，将标量结果写入容器 `/tmp`，不改变入口父 shell 的选项。原 `db/schema.sql` 按字节复制，不删除 `CREATE ROLE`、不预建角色、不替换 SQL。额外观察脚本和资源覆盖意味着这不是完全不变的 `docker compose up`。

随后运行真实安装诊断 CLI、真实应用 CLI、live/ready、原始 context 客户端模块和一轮原始 demo-story 模块。目标覆盖种子 20号 v1、显式批准后的 15号 v2、旧依据、409 和两种 403 权限控制。HTTP 在测试进程中经过限定单一 loopback origin 的计量包装，正文完整、有界物化后才交原客户端校验；不是未加计量的性能测试。没有浏览器、MCP、生产身份或模型调用。

边界为 64 个 HTTP、单响应 64 KiB、累计 HTTP 正文 1 MiB、声明范围内累计应用字节 8 MiB、180 秒工作及独立 60 秒清理，并设 240 秒总期限 timer。期限依赖事件循环获得运行机会，不是硬实时或运行时间 SLO。应用字节计入命令参数/标准流、应用 CLI 输出和 HTTP 正文；不计挂载文件、服务内部 PG、HTTP 头部/wire、Docker daemon 内部流量或堆分配，计量不构成内存硬上限。认证值和完整环境、初始化日志、响应正文不落盘。

清理先停止自己的应用/请求，再逐项检查项目容器及实际存在的精确卷/网络的归属，执行本项目 `down --volumes`；不执行 prune 或 `--remove-orphans`。之后按项目标签及精确资源标识/名称双重检查零残留。清理命令不因工作字节预算耗尽而被跳过。命令超时先终止再强制关闭，并给关闭确认单独期限；未确认关闭仍标记不确定，不能因 Docker 客户端退出就断言 daemon 没有创建资源。已尝试创建却未收到成功确认时，即使当前检查零残留，也保留临时配置并分别记录“当前检查为空”和“创建结果未知”。总期限 watchdog 会尝试停止自己的进程、记录资源未知并退出，不保证 daemon 资源已经关闭；异常期间的零残留检查也只是当时的观测，不保证外部 Docker 后续行为。报告还记录实际 Node/Compose/镜像、HEAD/dirty、明确列出的源码哈希及前后对照；不是整仓独立来源证明。
