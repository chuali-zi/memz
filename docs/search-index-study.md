# 标题搜索索引对照：暂不迁移

## 决定与证据

本轮不向应用库增加索引、扩展或改写搜索接口。真实应用角色下，实验GIN索引没有参与无匹配标题查询；管理员诊断查询使用了GIN，不能据此声称应用获得收益。实验还观察到写入WAL与索引空间增加。因此保留当前字面子串语义和RLS，记录扫描限制，而不是绕过权限来追求好看的计划。

这是当前PostgreSQL16实验环境的决定，不是“GIN永远无用”的结论。后续数据、策略或版本改变时应重新测量。

## 复现与对照

沿用[查询计划实验](query-plans.md)的PLAN_DATABASE_URL和npm run eval:plans。新阶段追加在同一个随机临时库，原始报告searchOptions字段记录全部结果；CI仍归档query-plan-evidence。实验模块为evaluation/search-options.js，应用不会调用它。

在2004条来源基础上新增两条字面通配符/反斜杠样例，共2006条，项目1为1005条。依次执行：

| 阶段 | 数据库结构 | 对比查询 |
|---|---|---|
| existing-indexes | 现有主键与(project_id,id)唯一索引 | 当前position条件；转义后的LIKE |
| experimental-gin | 另建lower(title)的GIN gin_trgm_ops索引 | 同上，RLS和角色不变 |
| after-removal | 删除仅本实验创建的索引与pg_trgm扩展 | 再次执行同一组查询 |

LIKE参数先将反斜杠、%和_转义，再包围两个%。10个关键词覆盖空串、无匹配、选择性长词、单字、数字片段、%、_、反斜杠及混合大小写。每个阶段两种查询都与明确的合成行逐条比较，另以用户4直接查询项目1确认0行；每个查询保存两份实际计划。不会把全文分词、前缀匹配或相似度阈值当成兼容替换，因为它们改变用户的字面子串语义。

读取前执行VACUUM ANALYZE，规划器配置不强制指定索引。用于结构定位的管理员查询单独标记ownerDiagnostic，不能作为应用角色性能基线。

## 权限与规划解释

PostgreSQL文档说明pg_trgm索引支持LIKE等运算，但并不保证每种查询都会选它：[pg_trgm索引支持](https://www.postgresql.org/docs/16/pgtrgm.html#PGTRGM-INDEX)。RLS策略通常先于用户查询条件执行，leakproof函数是例外；表所有者通常绕过RLS：[行安全策略](https://www.postgresql.org/docs/16/ddl-rowsecurity.html)。

本次从pg_proc读取到strpos与textlike均非leakproof；应用角色未使用GIN而owner诊断使用GIN，与这一安全约束一致。这是结合计划的解释，并非通过关闭RLS证明的因果实验。没有修改系统函数的leakproof属性、禁用RLS、设置BYPASSRLS或用SECURITY DEFINER包装搜索。

## 写入工作量与空间

每阶段以真实memz_app用户1执行两批各200行来源INSERT，保存EXPLAIN ANALYZE BUFFERS WAL；每批最后ROLLBACK。它测的是数据库直接写入，排除HTTP、幂等回执和审计，不能当成完整创建API的耗时。

开发环境一次实测中，现有索引两批WAL分别289962/289649字节，GIN阶段为436836/440048字节，移除后为289194/292404字节。GIN在写入前139264字节、两批回滚写入后442368字节；具体数值以同提交原始报告为准。回滚不意味着物理索引页面或序列值恢复；这也是记录写入前后空间而不是只看逻辑行数的原因。

这些是顺序、已预热、少量样本的工作量观察。写入间残留死元组、序列间隙、页面状态、WAL整页镜像等因素会变化，不能据此给出固定百分比、分位数或生产吞吐结论。报告保留原始值，不设置时间/WAL性能门槛。

## 安装、移除与数据保留验证

仅在随机临时库验证：

- BEGIN中安装扩展与索引后ROLLBACK，确认两者不存在。
- 实验索引重复安装，重跑已有001/002迁移；逐行核查业务表，来源策略保持不变。
- 应用角色不能创建索引，其他项目用户不能向项目1写来源，两者返回42501。
- 每次写入试验回滚后来源内容完全一致；实验结束删除索引和扩展后业务表与来源策略仍一致，并重新检查查询结果。

没有发布003迁移，因为尚无足够的应用角色收益证据。实验使用普通CREATE INDEX，不宣称已验证生产在线建索引、并发DDL或既有扩展依赖的通用回滚。不能把本实验的DROP EXTENSION命令用于用户数据库；实验库中的扩展由实验独占创建，最终整个临时库也会清理。
