# DeepSeek 产品效果实验：预先固定的协议

2026-11-06（Asia/Shanghai）。本轮用户已授权真实模型测试与 GitHub 推送；旧文件的“未授权模型调用/暂停推送”仅记录旧任务状态。

目标是检验**人工批准结构化事实后的读取价值**，以及显式精简 reader 格式的成本/质量取舍。不是自动抽取系统、OpenViking 对跑、论文复现或生产评估。全部材料为本项目原创合成数据，不发送用户数据。模型通过环境变量 DEEPSEEK_API_KEY 调用官方端点；不记录认证信息。

固定模型为实际 `/models` 可用的 `deepseek-flash`；非思考模式、temperature=0、JSON 输出、最多256输出 token、每次45秒、并发2、一次尝试，不自动重试。开发集2个项目×7题×4组×1次=56次；留出集4个新项目×7题×4组×2次=224次，共280次，最多预留71,680输出 token；另有一次连通性请求。实际计费 token/cache usage取提供方回执，缺失为null，不从字符数估算费用。没有假设可关闭提供方缓存。

四组共用问题、系统提示、模型参数：

1. `no_memory`：不提供上下文。
2. `full_history`：完整事件、来源及批准/待审/驳回状态，作为较强基线。
3. `memz_full`：真实PostgreSQL、RLS及只读客户端返回的当前事实单页快照，完整格式。
4. `memz_reader`：同一快照的显式精简投影，保留事实、确切修订、来源ID、完整来源标题/原文、不可信标记、一致性和分页边界。省去面向客户端的查询回执及审批人/候选字段，并使用紧凑JSON；原客户端合同保持不变。

每个项目9个事件、4项当前事实，含更新、待审、驳回和一段模拟指令污染原文。7类问题分别是当前更新值、待审干扰、驳回干扰、两事实组合、未知信息、被替代的历史值、带指令原文的事实。历史题故意保留：当前事实视图不含旧证据，应暴露能力边界。未知信息的正确拒答计质量成功；已知历史题拒答仍计任务失败，另报拒答行为。

开发/留出分割按项目，所有模板在模型调用前固定。留出只是实体和值不同，**模板同源，不能推断真实领域泛化**。精简格式也是预先指定的消融项，不能写成看到留出成绩后调优。模型没有gold、题型、预期值或答案标签；gold独立写入，只有离线评分器读取。

主指标：完整分母上的严格答案数组匹配；未知题正确拒答；精确来源ID集合；按类别和项目分解。有效JSON必须包含answer/abstain/source_ids三字段，非完整生成、异常、超时、未调用都计任务失败。重复请求不当独立问题。使用项目聚类bootstrap报告配对质量差值区间；仅4个留出项目，区间不能视为大规模证明。

记录实际输入/输出/cache tokens、逐请求时延、请求哈希、提供方请求ID/模型名、调用失败。原始逐题输出保留以便复核。模型生成在冻结导出上下文上测量，检索单独记录；**不宣称在线端到端延迟或TTFT**。审批是脚本执行的owner决策，不是假装自动抽取；导出时间不当作人工成本或纯写入时延。

固定项目范围后读取该项目全部4个已批准事实，不使用答案过滤事实或给出oracle检索词；完整历史也使用同样项目范围。单独探测把原问题直接传给substring接口的返回条数，量化自然语言接入缺口；不把这个弱路径作为主要质量对照。

研究依据：OpenViking固定版本的[L0/L1/L2](https://github.com/volcengine/OpenViking/blob/739e17f9172b9f595bfe4cc95293ec52d4686120/docs/en/concepts/03-context-layers.md)支持区分导航表示与完整证据；本轮独立实现确定性投影，不复制源码或引入生成摘要。[LongMemEval](https://arxiv.org/abs/2410.10813v2)将索引、检索、读取分开，覆盖更新、时间及拒答；本轮借鉴评测维度而非使用其数据/成绩。[MemGPT](https://arxiv.org/abs/2310.08560v2)启发工作上下文与持久历史分离；[A-MEM](https://arxiv.org/abs/2502.12110v11)启发未来可重建检索元数据，尚未实现图关联。

这些原始摘要/文档本轮重新核查；接口参数核查于[DeepSeek官方文档](https://api-docs.deepseek.com/api/create-chat-completion)。完整原论文机制分析另见已有研究记录，不能把摘要阅读写成全篇复现。

## 开发结果后的预注册修订（留出集调用前）

开发集56次请求全部完成：full_history 14/14，memz_full及memz_reader均12/14，no_memory 2/14。两项Memz失败均为历史值缺失。reader平均输入646 token，原格式962 token；不据此调整问题、gold或评分器。

针对这个开发集错误，新增第五组 `memz_history`：通过已有history分页接口与固定版本批量依据接口读取**同一项目的已批准修订**，包含当前及被替代的版本，保留完整原文。所有题统一使用这个组，不根据题型/gold挑证据。接口每页最多25条，显式nextBefore/truncated，不默默截断、拼接或宣称共同事务快照。它是显式历史读取能力，不是自动时间推理或自然语言路由。

先只在开发集增加14次history调用验证；随后冻结五组，在留出集28题×5组×2次=280次。加原开发56次，正式实验共350次，最多预留89,600输出token，另有1次连通性请求。此前四组预注册保留；新增组的选择只依据开发集，留出集尚未调用。开发集原四组不重复付费调用；完整留出组仍按题配对轮转。此修改不扩充为真实公开基准或第三方系统对跑。
